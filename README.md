# 小火箭日本节点故障转移

这是 Shadowrocket 的公开配置，不含节点、订阅地址、账号或密码。节点来自你自己在小火箭中添加的订阅。仅提供日本节点故障转移，不复制 Clash DNS 策略，也不添加解密、证书或脚本。

## 直接导入

配置下载与更新地址：

https://raw.githubusercontent.com/GitKUMA/shadowrocket-jp-fallback/main/jp-fallback.conf

1. 在小火箭首页先添加并更新自己的节点订阅。
2. 打开“配置”，点击“+”，粘贴上面的地址并下载配置。不同版本的按钮名称可能略有区别。
3. 选中并启用下载的配置，把“全局路由”设为“配置”。开启连接。
4. 查看“日本故障转移”组，确认出现日本节点，并执行一次组内连通测试。
5. 后续在远程配置操作中选择“更新配置”；节点订阅仍单独更新。本项目不承诺自动定时下载远程配置。

完整配置的规则：IPv4/IPv6 局域网及回环地址直连，中国 IP 直连，其余流量走日本故障转移。中国 IP 分类使用客户端 GEOIP 数据，不能等同于完整的国内域名分流。启用此文件会使用本文件的分流规则，不是对原手机配置的自动合并。先备份原手机配置。

## 保留现有分流

只包含故障转移组的文件：

https://raw.githubusercontent.com/GitKUMA/shadowrocket-jp-fallback/main/jp-fallback-group.conf

下载后保留文件名 `jp-fallback-group.conf`。在现有配置的 `[General]` 中按客户端“包含配置 / Include”入口包含该已下载配置（文本形式为 `include = jp-fallback-group.conf`）。若已有 include，先在客户端合并，不直接覆盖。

将你原有需要走代理的规则或策略组选项指向 `日本故障转移`，保留所有直连、拒绝及其他特殊规则。仅导入组文件不会自动把流量切到该组，也不要单独启用没有流量规则的组文件作为完整配置。保留现有分流的接入步骤需要人工操作。

## 策略边界

- `fallback`：当前候选不可用时切换其他可用候选；不是按最低延迟选节点。
- 参数：`interval=15`、`timeout=3`，单位按 Shadowrocket 配置格式为秒；15 秒/3 秒不是断线恢复时间承诺。不要把 Clash 的 `timeout=3000` 或 `lazy: false` 原样写入小火箭。
- 测试地址为 `https://www.gstatic.com/generate_204`；可达此地址不证明 Claude 等目标可用。
- 按节点名称匹配 🇯🇵、日本或独立单词 Japan（不区分大小写），排除流量、到期、官网等提示。名称不能证明节点真实地理位置。只写 JP、东京等名称的节点需自行添加“日本”备注或调整过滤式。
- 默认扫描客户端可供正则策略筛选的节点，不限定某一个订阅。多个机场的日本节点可能同时入组；需要限制单个订阅时，在客户端明确绑定订阅并再次检查候选。
- 没有日本候选时，需要先修正订阅或备注；不承诺自动回退到其他国家或直连。
- iOS 的运行和后台限制可能影响探测周期，不能保证 Clash 桌面端相同的持续探测行为、无缝切换或不掉登录。
